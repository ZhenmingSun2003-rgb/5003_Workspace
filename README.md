## 1. 项目简介

我们的研究基于 **World Values Survey Wave 7（WVS7）**，尝试利用受访者的人口统计特征、教育背景和社会经济情况，预测其就业状态（`Q279`）。`Q279` 包含全职、兼职、自雇、退休、家庭主妇／夫、学生、失业和其他，共 **8 个类别**，因此这是一个多分类问题。

**A1 已完成**数据清洗、探索性数据分析（EDA）和建模计划（Model Plan）；**A2 将在此基础上**完成模型训练、实验设计与调参，并对五种模型进行比较。我们的目标是分析预测关系，而不是从观察性数据中推断因果关系。

A1 的几个重要发现，也会帮助我们设计后续实验：

- **年龄**对区分学生和退休人群特别有帮助，其他就业类别之间则存在明显重叠。
- **性别**对部分就业类别（尤其 Housewife）有较强的区分作用，但单一特征不足以解释全部类别。
- **国家之间**的就业结构差异较大，值得引入较简洁的国家层面社会经济信息。
- **类别分布不平衡**：最大类别约为最小类别的 30 倍，因此不能只凭 Accuracy 判断模型好坏。

A1 已将原始的 **97,220 行、613 列**数据清洗为 **95,987 行、519 列**。仓库中的 CSV 是统一的数据起点；A2 的最终特征选择、`Income_Group` 构建以及各模型需要的编码、缩放等工作仍需完成。

## 3. A2 实验的共同思路

为了方便最后公平比较，建议大家沿用 A1 Model Plan 中已经确定的方向：

- **预测目标**：`Q279`，共八个类别。
- **预测特征**：围绕人口统计、教育和社会经济变量进行选择。A1 计划根据世界银行国家收入分类创建四档 `Income_Group`（Low / Lower-middle / Upper-middle / High income），并在最终建模时排除原始 `Country`。这一步属于 A2 的待完成工作。
- **数据划分**：按 `Q279` 进行分层训练／测试划分；五个模型尽量使用同一划分及相同的测试集。具体比例和随机种子可以先在小组内确定，再记录到 `baseline.Rmd`。
- **模型预处理**：类别编码、数值缩放等可根据算法特点安排；拟合预处理参数和调参时注意只使用训练数据，避免测试信息泄露。A1 计划不使用 survey weights，因为目标是个体预测，而不是总体推断。
- **统一评估**：以 **Macro F1** 为主要指标，同时记录 **Weighted F1、Accuracy、Confusion Matrix**，以及各类别的 Precision / Recall / F1，重点关注少数类别的表现。
- **最终选择**：除预测效果外，也考虑可解释性、计算成本及模型稳定性。若模型表现接近，可以讨论是否优先选择更简单、容易解释的方案。

考虑到数据量较大，kNN 和 SVM 若在调参时耗时过长，可以先缩小搜索范围或使用分层抽取的训练子集开展探索；**最终比较仍使用共同的测试集**。

## 4. 小组协作方式

为了让大家都能顺利并行推进，我们先采用比较简单的合作方式：**直接使用现有 `main` 分支，不必额外创建分支或 Pull Request。**

每位组员主要修改自己负责的模型 `.Rmd`，把模型专属的特征处理、训练、调参、评价、图表和文字解释集中在一个文件里。这样既容易整理实验过程，也能减少不同成员之间的代码冲突。

有几个小建议：

1. **共享 CSV 尽量保持原样。** 需要新增变量、转换格式或标准化时，在自己的实验代码中完成即可，不必覆盖原始共享数据。
2. **`baseline.Rmd` 先作为公共参考。** 如果需要修改共同的特征规则、数据划分或评估函数，我们先在群里简单讨论，避免某人的实验突然受到影响。
3. **尽量不改其他成员的 Rmd。** 如果发现问题，直接交流即可，具体修改由负责的同学处理会更方便。
4. **让实验能够复现。** 建议保留随机种子、特征选择、调参范围、关键结果和必要说明，并用相对路径读取 CSV。
5. **小步提交、只提交自己的文件。** 这样大家的进度都能及时同步，版本历史也更清楚。

例如，在仓库根目录读取数据可以使用：

```r
wvs <- read.csv("WVS_Wave7_cleaned_for_modelling.csv")
```

### Git 日常操作示例

开始工作前，如果本地没有未提交的修改，可以先同步仓库：

```bash
git switch main
git pull --ff-only origin main
```

以负责 kNN 的同学为例，完成一个阶段后：

```bash
git status
git add 03_kNN.Rmd
git commit -m "feat(knn): add initial experiments"
git pull --rebase origin main
git push origin main
```

其他模型只需替换文件名。建议使用 `git add 文件名`，避免 `git add .` 意外包含公共 CSV、临时数据或其他文件。如果遇到冲突，可以先在群里沟通，不需要强行覆盖其他人的工作。

### CSV 与 Git LFS

因为 CSV 比较大，仓库使用 **Git LFS** 存放数据文件：实际文件内容由 LFS 存储，普通 Git 版本历史主要记录文件指针；`.gitattributes` 用来声明相应的追踪规则，平时通常无需修改。

如果尚未安装 Git LFS，可以先安装并在仓库中运行：

```bash
git lfs install
git lfs pull
```
